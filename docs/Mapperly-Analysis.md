# Mapperly: Comprehensive Technical Analysis

> A complete reference on Mapperly — what it does, how it works internally, every major feature, and the current state of the project (as of v4.3.1, late 2025 / 2026). Written as a companion to `AutoMapper-Analysis.md` so the two can be read side-by-side.

---

## 1. Project Overview

**Mapperly** is a .NET object-to-object mapper implemented as a **Roslyn incremental source generator**. You declare a partial class with method signatures, decorate it with `[Mapper]`, and the compiler emits a fully-typed implementation at build time. Nothing is reflection-based at runtime; the generated code is what executes.

| Attribute | Value |
|---|---|
| Repository | `riok/mapperly` |
| Maintainer | **riok** (Swiss software organization; commercial support: hello@riok.ch) |
| Current stable version | **v4.3.1** (released 2025-12-22) |
| Preview channel | **v5.0.0-next.x** (generic user-implemented mappings, projection expressions) |
| Target frameworks | **.NET 5+** and **.NET Framework 4.x**; requires **C# 9+** and **Roslyn 4.0+** |
| Language | C# (source generator) |
| Adoption | ~4.1k★, 217 forks, ~21.5M total NuGet downloads |
| Packages | `Riok.Mapperly` (the generator) + `Riok.Mapperly.Abstractions` (attributes) |
| **License** | **Apache-2.0** (permissive, no copyleft, no commercial license needed) |

### Tagline / value proposition
A mapper with the ergonomics of a runtime DI library and the performance of hand-written code, by emitting that hand-written code for you. Zero reflection at runtime, fully trim- and Native-AOT-safe, every unmapped property surfaces as a build-time analyzer warning.

### When NOT to use it
Mapperly is the wrong choice when:
- You need to call **async** code or look up **DI services** *inside* the mapping itself (the generator emits sync code with no service locator). The escape hatch — user-implemented partial methods — works, but if most of your maps need it, you're fighting the tool.
- You need to register or modify mappings at **runtime**. Mapperly is purely declarative and compile-time.
- Your code generator infrastructure is fragile (older SDKs, unusual build setups). Source generators have stricter SDK/Roslyn requirements than a NuGet runtime library.

For modern .NET 8/9 services, libraries, and especially Native-AOT or trimmed projects, it's a strong fit.

## 2. Core Architecture & Technical Approach

The defining property of Mapperly — and the one to anchor every other decision on — is that **all mapping code is generated at compile time**. Read this section first; the rest of the document hangs off it.

### 2.1 The user surface
You write a partial class plus method signatures. No bodies.

```csharp
[Mapper]
public partial class CarMapper
{
    public partial CarDto CarToCarDto(Car car);
    public partial void Update(CarDto source, Car target);
}
```

The `[Mapper]` attribute (from `Riok.Mapperly.Abstractions`) turns the class into a generator target. Each `partial` method is a mapping contract.

### 2.2 What the generator emits
At build time, Mapperly walks the source/target types, applies its conventions, and emits a sibling `.g.cs` file completing every partial method. The generated body is straight-line C# property assignment with explicit `null` checks, conversions, and collection iteration — what you would have written by hand if it weren't tedious.

Default emission location:
```
obj/{Configuration}/{TFM}/generated/{Assembly}/Riok.Mapperly/*.g.cs
```

Each file carries `// <auto-generated />` and `[GeneratedCode]` so analyzers and style tools treat it as machine output.

### 2.3 Inspecting the generated code
Persist the files into source control or just into a known folder:
```xml
<PropertyGroup>
  <EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>
  <CompilerGeneratedFilesOutputPath>Generated</CompilerGeneratedFilesOutputPath>
</PropertyGroup>
```
Or one-shot at the command line:
```
dotnet build /p:EmitCompilerGeneratedFiles=true
```

Visual Studio, Rider, and `dotnet build` all surface the generated files in their respective project trees. Reading them is the canonical way to debug a Mapperly mapping.

### 2.4 Runtime model
- **Zero reflection.** No `Type` lookups, no expression compilation, no `Activator.CreateInstance`.
- **Zero startup cost.** The mapping IL is in your assembly, JIT-compiled with the rest of your code.
- **Trim-safe / AOT-safe.** Because nothing is dynamic, the linker can prove what's used.
- **Per-call overhead** is essentially that of the hand-written equivalent — just property assignments and `new` calls.

### 2.5 Comparison framing
The contrast with AutoMapper is structural, not stylistic:

| | AutoMapper | Mapperly |
|---|---|---|
| Code lives | At runtime — `Expression` trees compiled to delegates on first use | At compile time — emitted into your assembly |
| Customization | `Profile` classes, fluent `CreateMap` calls | Attributes on partial classes/methods |
| Validation | `AssertConfigurationIsValid()` in a unit test | Roslyn analyzer warnings (RMG###) at build |
| Reflection | Yes (driving expression construction) | None |
| AOT/Trim | Limited / problematic | Fully supported |
| Runtime config | Yes | No (everything is declarative) |

## 3. Configuration Model

### 3.1 The `[Mapper]` attribute
The single root of configuration. Set on the partial class:

```csharp
[Mapper(
    PropertyNameMappingStrategy = PropertyNameMappingStrategy.CaseInsensitive,
    EnumMappingStrategy         = EnumMappingStrategy.ByName,
    EnumMappingIgnoreCase       = true,
    UseDeepCloning              = false,
    UseReferenceHandling        = false,
    ThrowOnMappingNullMismatch  = true,
    AllowNullPropertyAssignment = true,
    RequiredMappingStrategy     = RequiredMappingStrategy.Both)]
public partial class CarMapper { /* signatures */ }
```

Property surface (the working set):

| Property | Purpose |
|---|---|
| `PropertyNameMappingStrategy` | `CaseSensitive` (default), `CaseInsensitive`, snake_case variants |
| `RequiredMappingStrategy` | `Both` (default) / `Source` / `Target` — which side must be fully covered |
| `IgnoreObsoleteMembersStrategy` | `None` / `Both` / `Source` / `Target` — handling of `[Obsolete]` members |
| `AutoUserMappings` | Auto-discover user-implemented partial methods (default `true`) |
| `UseDeepCloning` | Clone collections/objects rather than reuse references |
| `StackCloningStrategy` | Element ordering when cloning `Stack<T>` |
| `UseReferenceHandling` | Enable cycle-safe mapping via an `IReferenceHandler` |
| `ThrowOnMappingNullMismatch` | Throw `ArgumentNullException` when a non-nullable mapping returns null |
| `ThrowOnPropertyMappingNullMismatch` | Same, at property level |
| `AllowNullPropertyAssignment` | Allow null source → nullable target (default `true`) |
| `EnabledConversions` | `MappingConversionType` flags — turn built-in conversion families on/off |
| `EnumMappingStrategy` | `ByValue` (default) / `ByValueCheckDefined` / `ByName` |
| `EnumMappingIgnoreCase` | Case-insensitive name matching |
| `EnumNamingStrategy` | Naming for string ↔ enum conversion (CamelCase, PascalCase, SnakeCase, …) |

### 3.2 Assembly-level defaults
```csharp
[assembly: MapperDefaults(EnumMappingIgnoreCase = true,
                          PropertyNameMappingStrategy = PropertyNameMappingStrategy.CaseInsensitive)]
```

Sets a baseline for every `[Mapper]` in the assembly. Useful for consistency in larger codebases.

### 3.3 Configuration precedence
From lowest to highest:
1. MSBuild properties
2. `[MapperDefaults]` (assembly)
3. `[Mapper]` (class)
4. Per-method / per-property attributes (`[MapProperty]`, `[MapEnum]`, …)

Higher levels always win. There is no runtime override — once compiled, the configuration is frozen.

## 4. Conventions

Mapperly's conventions are simpler than AutoMapper's because they don't have to drive a runtime engine; they just decide what code to emit.

### 4.1 Name matching
- Properties are matched by name (case-sensitive by default; opt into `CaseInsensitive` via `PropertyNameMappingStrategy`).
- Snake_case ↔ PascalCase strategies are first-class.
- Member discovery walks public instance properties on both sides.

### 4.2 Flattening
Automatic flattening (e.g. `source.Customer.Name → CustomerName`) is supported when the path is unambiguous. Where the convention can't disambiguate, declare it explicitly with `[MapNestedProperties]` or `[MapProperty]`.

### 4.3 Convention determinism
A key property: **conventions are evaluated at compile time, with full information**. If two source paths could fill the same target, the analyzer emits a diagnostic — you don't discover the ambiguity in production.

## 5. Customization Surface (per-property override hooks)

Listed in order of how often you'll reach for them.

### 5.1 `[MapProperty]`
The everyday workhorse. Map a differently-named source path, format a value, or route through a user method:
```csharp
[MapProperty(nameof(Source.Name),       nameof(Target.FullName))]
[MapProperty(nameof(Source.CreatedAt),  nameof(Target.Created),
             StringFormat = "yyyy-MM-dd")]
[MapProperty(nameof(Source.Amount),     nameof(Target.AmountText),
             Use = nameof(FormatAmount))]
public partial Target Map(Source src);
```

Properties of `[MapProperty]`:
- `Source` / `Target` — the names or `nameof()` expressions for the two sides; supports dot paths for nested members.
- `StringFormat` — format string applied when the source implements `IFormattable`.
- `FormatProvider` — name of a field or property on the mapper class (e.g. a culture).
- `Use` — name of a user-implemented mapping method to invoke for this property.
- `SuppressNullMismatchDiagnostic` — silence the RMG089 warning for this property.

### 5.2 `[MapPropertyFromSource]`
Map the *whole source object* into a target property (typically the parent into a child DTO):
```csharp
[MapPropertyFromSource(nameof(Target.Origin), Use = nameof(BuildOrigin))]
public partial Target Map(Source src);

private OriginDto BuildOrigin(Source src) => new(src.City, src.Country);
```

### 5.3 `[MapValue]`
Set a constant or computed value on a target property — no source involved:
```csharp
[MapValue(nameof(Target.Schema), "v2")]
[MapValue(nameof(Target.GeneratedAt), Use = nameof(Now))]
public partial Target Map(Source src);

private static DateTime Now() => DateTime.UtcNow;
```

### 5.4 `[MapNestedProperties]`
Tell Mapperly to flatten/unflatten through a particular path when the convention can't see it:
```csharp
[MapNestedProperties(nameof(Source.Address))]
public partial Target Map(Source src);
```

### 5.5 `[MapperIgnoreSource]` / `[MapperIgnoreTarget]`
Take a member out of consideration (and out of the unmapped-member analyzer):
```csharp
[MapperIgnoreSource(nameof(Source.InternalNotes))]
[MapperIgnoreTarget(nameof(Target.LegacyField))]
public partial Target Map(Source src);
```

## 6. User-Implemented Partial Methods (the escape hatch)

When the generator can't (or shouldn't) figure something out, you write it. This is Mapperly's equivalent of AutoMapper's `IValueResolver` / `ITypeConverter` — but rather than a parallel hierarchy of interfaces, it's just a method on the same partial class, which the generator picks up and calls.

```csharp
[Mapper]
public partial class CarMapper
{
    public partial CarDto MapToDto(Car car);

    private string FormatVin(string raw) => raw.ToUpperInvariant();   // auto-discovered
}
```

If the generator finds a method whose signature matches a needed type-pair (`Source → Target`), it calls that method instead of generating one. Behavior is governed by:

| Attribute / setting | Effect |
|---|---|
| `[UserMapping(Default = true)]` | Mark this as the preferred mapping for the type-pair when multiple match |
| `[UserMapping(Ignore = true)]` | Exclude from auto-discovery |
| `Mapper.AutoUserMappings = false` | Discover only methods explicitly annotated with `[UserMapping]` |
| `[MapProperty(..., Use = nameof(X))]` | Reference a user method explicitly for one property |
| `[MapperIgnore]` | Excludes a user method from being treated as a converter |

This is also how you bring DI services or other state into a mapping: make the mapper an instance class, inject what you need, and write user methods that reference it.

## 7. Type & Value Conversions

Mapperly applies a fixed priority list of conversion strategies. The first that matches wins. Roughly:

1. Direct assignment (same type / implicit reference)
2. Queryable projection mapping (when the call is `IQueryable<TSource> → IQueryable<TTarget>`)
3. Dictionary mapping
4. Enumerable mapping (collections)
5. Span / Memory mapping
6. Implicit operators
7. Static `Parse` methods
8. Constructors taking the source type
9. String ↔ enum
10. Enum ↔ enum (by value or by name)
11. Explicit operators
12. `ToString` (with `IFormattable` / format support)
13. Instance `ToTarget()` / `Create()` / `CreateFrom()` / `From()` methods
14. Static factory methods (`ToTTarget`, `Create`, `CreateFrom`, `From`)
15. `DateTime` ↔ `DateOnly` / `TimeOnly`
16. `IConvertible` fallback
17. User-implemented mapping methods (also registered into this lookup)

To turn whole families off, use the `EnabledConversions` flag enum:
```csharp
[Mapper(EnabledConversions = MappingConversionType.All & ~MappingConversionType.ToStringMethod)]
public partial class M { /* ... */ }
```

User methods you don't want auto-discovered as converters get `[MapperIgnore]`.

## 8. Object Mapping Behaviors

### 8.1 New instance vs update
Two method shapes are supported on the same partial class:
```csharp
public partial Target Map(Source src);                // creates a new Target
public partial void   Update(Source src, Target tgt); // mutates an existing Target
```
For `Update`, scalar/value-type properties are overwritten; nested objects are recursively updated where a matching update mapping exists, otherwise replaced.

### 8.2 Constructor selection
Priority:
1. Constructor marked with `[MapperConstructor]`
2. Otherwise governed by `PreferParameterlessConstructors` (default `true`)
3. Parameter names matched **case-insensitively** against source members; `[MapProperty]` can rename the binding

This makes records and immutable types first-class destinations:
```csharp
public record CarDto(string Make, string Model, int Year);

[Mapper]
public partial class CarMapper
{
    public partial CarDto MapToDto(Car car);
}
```

### 8.3 Init-only / required properties
Init-only and `required` properties are populated through the object initializer that the generator emits — there's no runtime trick involved. Nullability rules from the `[Mapper]` attribute apply.

## 9. Collections

### 9.1 Supported destination shapes
Single source mapping, many destination shapes — no extra configuration:
- `List<T>`, `IList<T>`, `ICollection<T>`, `IReadOnlyCollection<T>`, `IReadOnlyList<T>`
- `IEnumerable<T>`
- `T[]`
- `ImmutableArray<T>`, `ImmutableList<T>`, `ImmutableHashSet<T>`, …
- `Span<T>` / `Memory<T>` (where applicable)
- Dictionaries (`IDictionary<TK,TV>`, `Dictionary<TK,TV>`, immutable variants)
- `Stack<T>`, `Queue<T>`, sets

Element mapping is recursive — Mapperly applies whatever mapping it has for the element types.

### 9.2 Deep cloning
Off by default (cheaper). Turn on per-mapper:
```csharp
[Mapper(UseDeepCloning = true)]
```
Even with deep cloning enabled, **`IQueryable` projections are never deep-cloned** — that would be incompatible with expression-tree translation.

### 9.3 `StackCloningStrategy`
Controls element ordering when copying a `Stack<T>` (preserve push order vs reverse). A small concession to a real-world ambiguity.

## 10. Inheritance & Polymorphism

`[MapDerivedType]` lets a single mapping method dispatch on the runtime source type:

```csharp
[Mapper]
public partial class AnimalMapper
{
    [MapDerivedType<Dog, DogDto>]
    [MapDerivedType<Cat, CatDto>]
    public partial AnimalDto Map(Animal animal);
}
```

Or pre-C#11:
```csharp
[MapDerivedType(typeof(Dog), typeof(DogDto))]
[MapDerivedType(typeof(Cat), typeof(CatDto))]
```

Generator output is a `switch` expression on the runtime type. Rules:
- Each source type must appear at most once (analyzer enforces uniqueness).
- Multiple sources may map to one target.
- An unrecognized source type at runtime throws `ArgumentException`.
- Other configuration on the mapping method applies, except where a more-specific user-defined mapping exists for an exact type pair.

## 11. Reference Handling & Cycles

Cyclic graphs are off by default. Turn on per-mapper:
```csharp
[Mapper(UseReferenceHandling = true)]
public partial class GraphMapper { /* ... */ }
```

The generated code accepts (or constructs) an `IReferenceHandler` (from `Riok.Mapperly.Abstractions.ReferenceHandling`). The default `PreserveReferenceHandler` records source→target pairs so a previously-mapped instance is reused rather than re-mapped, breaking cycles and preserving shared references.

To plug in a custom handler:
```csharp
public partial Target Map(Source src, [ReferenceHandler] IReferenceHandler handler);
```

## 12. Queryable Projections

Mapperly's equivalent of AutoMapper's `ProjectTo` is a partial method that takes and returns `IQueryable<T>`:

```csharp
[Mapper]
public partial class CarMapper
{
    public partial IQueryable<CarDto> ProjectToDto(IQueryable<Car> source);
}
```

Use it directly with EF Core:
```csharp
var dtos = mapper.ProjectToDto(db.Cars.Where(c => c.Year >= 2020)).ToList();
```

### 12.1 What's different from AutoMapper
The expression tree is built **at compile time** by the source generator and embedded in your assembly. AutoMapper builds the equivalent expression at first use, at runtime, by walking the configured maps. Functionally similar; operationally different — Mapperly's projection has no warm-up cost, and any incompatibility is a build error rather than a runtime exception.

### 12.2 Limitations
Projections must survive translation by the LINQ provider, so a long list of in-memory features doesn't apply:
- No object factories
- Optional constructor parameters are ignored
- No `EnumMappingStrategy.ByName` (only `ByValue`)
- No reference handling
- No deep cloning
- Nullable-reference-type checks are disabled (provider doesn't model them)
- Validation flags like `ThrowOnPropertyMappingNullMismatch` are ignored
- User-implemented methods used inside a projection must be expression-bodied or otherwise inlinable; if not, the generator emits **RMG068**

The trade-off mirrors AutoMapper's `ProjectTo` constraints, just enforced at build time.

## 13. Dependency Injection

Mapperly mappers are typically **stateless** and trivially injectable. Two patterns:

### 13.1 Static composition
For a mapper with no dependencies, you can mark it static and reference it from another mapper:
```csharp
[Mapper]
public static partial class StringMapper
{
    public static partial string Trim(string value);
}

[Mapper]
[UseStaticMapper<StringMapper>]
public partial class CarMapper
{
    public partial CarDto MapToDto(Car car);   // can call StringMapper.Trim
}
```

### 13.2 Instance mapper with DI
Treat the partial class like any other service:
```csharp
[Mapper]
public partial class CarMapper(ICurrencyService currency)
{
    public partial CarDto MapToDto(Car car);

    private string FormatPrice(decimal v) => currency.Format(v);  // user method using DI
}

// Registration
services.AddSingleton<CarMapper>();
```

Mapperly mappers are safe as Singleton (they hold no per-call state). Scoped is fine if they wrap scoped services.

### 13.3 The two NuGet packages
- `Riok.Mapperly` — the source generator. Reference-only at build time.
- `Riok.Mapperly.Abstractions` — the attributes (`MapperAttribute`, `MapPropertyAttribute`, `MapDerivedTypeAttribute`, `UseStaticMapperAttribute`, `IReferenceHandler`, …). Must be referenced because your code uses these attributes.

That's the entire ecosystem from the publisher.

## 14. Diagnostics & Validation (compile-time)

This is the structural counterpart to AutoMapper's runtime `AssertConfigurationIsValid()` — and arguably the single biggest day-to-day quality-of-life advantage of the source-generator approach.

### 14.1 The RMG diagnostic family
Mapperly emits **`RMG001`–`RMG094`** (and growing) as Roslyn analyzer diagnostics during build. The ones you'll see most:

| Code | Meaning |
|---|---|
| **RMG007** | Property cannot be mapped (no conversion known) |
| **RMG020** | Source member is not mapped to any target member |
| **RMG066** | No members are mapped in an object mapping |
| **RMG068** | User-implemented method cannot be inlined into an expression tree (queryable projection) |
| **RMG089** | Mapping nullable source to non-nullable target member |

Each diagnostic points at the offending attribute, partial method, or member — IDEs surface them inline.

### 14.2 Tuning severity
Standard Roslyn mechanisms apply:
- **`.editorconfig`**: `dotnet_diagnostic.RMG020.severity = error`
- **`SuppressMessageAttribute`** in code
- **`#pragma warning disable RMG089`** for one site
- **CSPROJ**: `<WarningsAsErrors>RMG020;RMG066</WarningsAsErrors>` to make CI fail on drift

### 14.3 `RequiredMappingStrategy`
Tightens the *expected coverage* of a mapping at the configuration layer — `Both` (default) requires every member on both sides to be accounted for; `Source` and `Target` relax accordingly. Combined with treat-as-error settings, this gives you build-time guarantees that AutoMapper can only achieve via a unit test.

### 14.4 vs AutoMapper
With AutoMapper, missing a destination property after a refactor is a *runtime* exception in your validation test (or, worse, a silent default value). With Mapperly, the same change is a *compile error* in CI — caught before the assembly even ships.

## 15. Async & External-Service Limits

Because the generator emits sync, statically-resolvable code, it cannot:
- emit `await` or generate `Task`/`ValueTask`-returning methods you didn't declare,
- look up services via `IServiceProvider` inside generated bodies,
- branch on runtime config that isn't visible at compile time.

The supported workarounds:
1. **User-implemented partial methods** for any logic that needs DI services or computed state.
2. **Materialize-then-map**: do the async work outside (e.g., `await dbContext.Cars.ToListAsync()`), then pass the result to a sync mapping method.
3. **Instance mappers with constructor-injected dependencies**: keep the generated mapping pure, route side-effects through a user method that consumes the injected service.

If your mapping fundamentally is async (e.g., it must call an external HTTP service per row), Mapperly is not the layer where that should happen — pull that work into a service and feed Mapperly synchronous, prepared inputs.

## 16. Enums

Enums get their own configuration surface because there are several legitimate ways to map them.

### 16.1 Strategy
```csharp
[Mapper(EnumMappingStrategy = EnumMappingStrategy.ByName,
        EnumMappingIgnoreCase = true)]
```
- **`ByValue`** (default) — match by underlying integer value.
- **`ByValueCheckDefined`** — match by value but throw if the integer doesn't correspond to a defined target member.
- **`ByName`** — match by member name (with `EnumMappingIgnoreCase` to ignore case).

### 16.2 Naming for string ↔ enum
`EnumNamingStrategy` controls how an enum member becomes (or is parsed from) a string:
- `MemberName` (verbatim)
- `CamelCase`, `PascalCase`, `SnakeCase`, `UpperSnakeCase`, `KebabCase`, `UpperKebabCase`
- `ComponentModelDescriptionAttribute` (use `[Description]`)
- `SerializationEnumMemberAttribute` (use `[EnumMember]`)

### 16.3 Per-method / per-value overrides
```csharp
[Mapper]
public partial class M
{
    [MapEnum(EnumMappingStrategy.ByName)]
    [MapEnumValue(Source.Legacy,  Target.Compat)]
    [MapperIgnoreSourceValue(Source.Internal)]
    [MapperIgnoreTargetValue(Target.Reserved)]
    public partial Target ToTarget(Source s);
}
```

### 16.4 Fallback / strict mode
A fallback value can be specified for unmapped source values; alternatively `RequiredEnumMappingStrategy` enforces that every value is accounted for, surfacing gaps as diagnostics.

## 19. Production Patterns & Pitfalls

### 19.1 Treat RMG diagnostics as errors in CI
The single highest-leverage configuration change. Add to your `.editorconfig` or CSPROJ:
```xml
<WarningsAsErrors>RMG020;RMG066;RMG089</WarningsAsErrors>
```
A renamed source property now fails the build, not a unit test.

### 19.2 Inspect the generated code when behavior is surprising
Set `EmitCompilerGeneratedFiles = true` and read the `.g.cs`. Faster than working backwards from a wrong field assignment.

### 19.3 IDE diagnostic latency
Source generators run at build, not on every keystroke. If the IDE shows stale RMG diagnostics, force a rebuild — it's not a Mapperly bug.

### 19.4 SDK / Roslyn requirements
The generator targets Roslyn 4.0+ and C# 9+. Old build agents and old SDKs (some pinned 3.x global.json setups) will silently produce no output. Lock the SDK version in `global.json` to a known-good 8.x/9.x.

### 19.5 Don't fight the sync-only model
If you're tempted to make a mapping async, the right answer is to push the async work out and feed Mapperly synchronous, ready-to-map data. Resist the urge to wrap everything in user partials.

### 19.6 Use partial classes the same way they exist for any other source generator
You can split the partial class across files — put the `[Mapper]` attribute and signatures in one, user-implemented helper methods in another. The generator handles it like any other partial.

### 19.7 Static vs instance mappers
Default to **instance** mappers in DI-driven applications (consistent registration, easy to mock). Use **static** only when you have a leaf mapper with no dependencies, and reference it via `[UseStaticMapper<T>]` from the consuming mapper.

### 19.8 Don't over-customize
Every `[MapProperty]` you add is a hint that the convention failed. If you're adding more than a handful per type, restructure the DTO names instead — the convention is doing more work for you than the manual overrides.

## 20. Documentation Map, Summary, and Mapperly vs AutoMapper

### 20.1 Documentation map
Official docs at <https://mapperly.riok.app/>. Sections (as of v4.3.1):

- **Getting Started** — Installation, first mapper, generated code inspection
- **Configuration** — Mapper attribute, MapperDefaults, conversions, constructor mappings, derived types, enum mappings, queryable projections, reference handling, user-implemented methods, analyzer diagnostics
- **API Reference** — every attribute in `Riok.Mapperly.Abstractions`
- **Migration / Upgrading** — version-by-version guides

### 20.2 One-line summary by layer

| Layer | What it is |
|---|---|
| **Mental model** | A Roslyn source generator that, given a partial class with method signatures and `[Mapper]`, emits the implementation at build time. |
| **Convention engine** | Compile-time name matching with optional case-insensitive / snake_case strategies and configurable null/required behavior. |
| **Customization surface** | Attributes on methods (`[MapProperty]`, `[MapValue]`, `[MapPropertyFromSource]`, `[MapNestedProperties]`, `[Mapper{Source,Target}Ignore]`, `[MapDerivedType]`, `[MapEnum]`, `[MapEnumValue]`) plus user-implemented partial methods as the universal escape hatch. |
| **Read-side optimization** | Generate an `IQueryable<TDto>` partial method whose body is a compile-time-built expression — embedded in the assembly, no warm-up. |
| **Productivity safety net** | Roslyn analyzer diagnostics (RMG###) at build time — promotable to CI errors. No runtime test needed. |
| **Business model (2026)** | Apache-2.0; no licensing entanglements; commercial support optional via riok. |

### 20.3 Mapperly vs AutoMapper — side-by-side

| Concern | Mapperly | AutoMapper |
|---|---|---|
| **Where mapping code lives** | Your assembly, generated at build | Built at runtime from `Profile`s, compiled to delegates on first use |
| **Reflection at runtime** | None | Used during expression construction |
| **Native AOT / trimming** | First-class | Limited |
| **Startup cost** | Zero | Configuration build + first-use compilation |
| **Per-call cost** | ≈ hand-written | ≈ hand-written after warm-up |
| **Configuration model** | Attributes on `partial class` | Fluent `CreateMap` in `Profile`s |
| **Validation timing** | Build (RMG analyzer) | Runtime (`AssertConfigurationIsValid()` in test) |
| **Queryable / `ProjectTo`** | Generated `IQueryable<T>` partial method | `mapper.ProjectTo<T>(IQueryable<T>)` extension |
| **DI inside mapping** | Instance mapper + user partial methods | `IValueResolver` / `ITypeConverter` / `IMappingAction` resolved from container |
| **Async** | Not supported in generated code | Not directly supported either, but easier to wrap |
| **Runtime configuration** | None (compile-time only) | Yes (build new `MapperConfiguration`) |
| **Inheritance / polymorphism** | `[MapDerivedType]` → switch | `Include` / `IncludeBase` / runtime-type lookup |
| **License** | Apache-2.0 | RPL-1.5 + commercial (since v15, July 2025) |
| **Maturity / adoption** | ~4.1k★, 21.5M downloads, growing | 10k★+, hundreds of millions of downloads, established |
| **Best for** | New projects, AOT/trim targets, performance-sensitive paths, build-time guarantees | Mature codebases already on it, scenarios needing runtime mapping config, deep ecosystem integrations |

### 20.4 Choosing
- **Greenfield .NET 8/9 service or library**, especially with AOT or trimming targets → Mapperly.
- **Existing AutoMapper codebase** with extensive custom resolvers, runtime profile composition, or many `IValueResolver`s with DI → keep AutoMapper unless you have a specific reason to migrate.
- **Library author** distributing to a wide audience → Mapperly's compile-time model and Apache-2.0 license avoid forcing a licensing decision on consumers.
